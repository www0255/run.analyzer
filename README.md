## 一句话定位

把一份普通的跑步记录表，变成一份看得懂的数据分析结论，和一份练得下去的训练方案。

## 目标用户与场景（双模式）

侧边栏用 radio 在两种模式间一键切换，同一份数据、两种口径：

| 模式 | 面向的人 | 看的东西 |
| --- | --- | --- |
| **A. 通用跑者模式** | 业余跑者、学生、刚入门的健身人群 | 里程/时长/配速/心率的变化趋势，以及针对当前水平的训练建议与周计划 |
| **B. 警校体能考核模式** | 需要准备体能测试的警校学生 | 把「配速(min/km)」直接折算成 **1000 米用时**（如配速 6.2 → 6 分 12 秒），画折算趋势图，并叠加一条可自行拖动的**参考目标线**（默认 270 秒 = 4 分 30 秒，可自行调整） |

> 说明：参考目标线只是使用者自己设定的参考值，**不代表任何官方标准或体测达标认证**，页面文案也写的是「参考目标线（可自行设置）」。

## 解决的问题

1. 跑步 App 给的是图表，不是结论：数据看得见，但「我该练什么、下周怎么排」没人回答。
2. 想用 AI 分析，先得会配置 API、会填 Key、会处理 401 和超时——大多数人卡在这一步。
3. 警校学生关心的是「1000 米能不能进 X 分」，而手环给的是 min/km，口径不一致，需要一次换算。

Run Analyzer 把这三件事收进一个网页：传表 → 出结论 → 出方案，并且**离线也能演示**。

## 与数据警务技术专业的契合点

这个作品的本质是一条数据链路：采集 → 清洗校验 → 指标折算 → 结论与决策建议，与我专业训练的处理流程是同一件事。
- **采集与清洗**：缺列逐条列出、坏日期跳过并说明、NaN 剔除并提示行数，先把数据可用性做扎实。
- **指标折算**：把 min/km 折算成 1000 米用时，把原始记录换成本场景真正关心的口径。
- **决策**：分析结论与训练方案要落到「下一次怎么练」，而不是停在图表上。
选「1000 米口径转换」作为切口：设备给的是 min/km，场景真正关心的是跑完 1000 米用多久，先对齐口径，后面的分析与建议才站得住。

## 核心功能

1. **CSV 上传 + 输入校验与清洗**：缺必需列时逐条列出缺哪几列；日期列解析失败的行会说明并跳过；数值列出现 NaN 的行会被剔除，并在页面上提示剔除行数。
2. **通用跑者分析**：里程、时长、配速、心率的变化趋势图 + 当前水平判断 + 训练建议。
3. **体能训练方案生成**：基于上传数据由 AI 生成结构化的训练方案（目标、周计划、强度建议、注意事项）。
4. **警校体能考核视图**：配速 → 1000 米用时折算、折算趋势折线图、可调参考目标线，用于自己盯自己的差距。
5. **演示模式 / 真实 AI 模式双通道**：默认开「演示模式」，从预置 JSON 直接读结果并渲染，页面顶部有醒目徽标「演示模式 · 预置样例结果」；评委点一下就出结果，零配置、零网络依赖。关掉演示模式才走真实 AI。

## 技术与 AI 使用

- 技术栈：Python + Streamlit（界面）、pandas（数据校验与清洗）、Plotly（交互图表）、openai SDK（OpenAI 兼容 chat.completions 调用）。
- 真实 AI 模式：用户自行填写 Base URL / 模型名 / API Key（password 输入框，不落库、不打印），走 OpenAI 兼容 `chat.completions`，请求超时 30 秒。
- 健壮性：网络失败、401、超时等任何异常都会被捕获，页面显示友好提示并**自动降级为演示结果**，绝不把报错栈甩到页面上、不让页面崩溃。
- 日志：用 `logging` 输出到 stdout，记录文件名/行数、当前模式、AI 调用耗时、异常类型；**任何情况下都不打印 API Key**。
- 密钥管理：`st.secrets` 可提供默认配置（`AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL` / `VISION_MODEL`，见下方「AI 服务配置」）；密钥不进仓库、不写进代码。

### AI 使用声明（A 类 · 作品功能中包含 AI 能力）

本作品**属于 A 类**：AI 是产品功能的一部分，而非装饰。用户上传数据后，应用会把清洗后的统计摘要交给大模型，由模型生成「数据分析结论 + 体能训练方案」并渲染在页面上；没有 AI 时只能看到图表，拿不到结论与方案。为保证评审现场可用，AI 能力配有演示模式兜底：AI 不可用时不隐藏功能，而是明确标注「演示模式 · 预置样例结果」。

### AI 使用声明（B 类 · 开发交付过程中使用 AI）

本作品**同时申报 B 类**，开发过程有明确的 AI 参与，并会在 PPT 中单页说明：

| 环节 | AI 参与方式 | 人的职责 |
| --- | --- | --- |
| 需求梳理 | 用大模型把「跑者 + 警校体能」两类场景拆成功能清单与验收点 | 决定做什么、不做什么 |
| 编码 | AI 辅助生成 Streamlit 页面骨架、数据校验分支、异常降级逻辑的初稿 | 逐段阅读、改写、跑通 |
| 调试 | 把报错贴给 AI 定位原因，再自己验证修复 | 复现问题、确认修复 |
| 文档 | AI 起草 README / 提交表 / 讲稿结构 | 校对事实、去掉夸大表述 |
| 测试 | AI 给出边界用例清单（缺列、坏日期、NaN、401、超时） | 实际逐条点一遍 |

原则：AI 负责「起草与提速」，人负责「判断与负责」——所有合并进仓库的代码，作者都读过一遍并能解释。

## AI 服务配置（Secrets 与预设）

配置优先级：`st.secrets` 提供默认值，侧边栏手动填写优先覆盖。

- `AI_BASE_URL`：接口地址，缺省 `https://api.openai.com/v1`。
- `AI_MODEL`：文本分析模型，缺省 `gpt-4o-mini`。
- `VISION_MODEL`：截图识别模型，缺省回退到 `AI_MODEL`。
- `AI_API_KEY`：密钥，回退 `DEEPSEEK_API_KEY` → 回退 `OPENAI_API_KEY`。

- 服务商预设：侧边栏下拉可选 **DeepSeek / OpenAI / 自定义**。选 DeepSeek 自动填 `base_url=https://api.deepseek.com`、文本与视觉模型均为 `deepseek-flash`（官方当前模型，对应 V4.1-Flash-1017，官方文档称其支持图片输入）；切换预设不会清空已填的 API Key。
- 视觉模型必须支持图片输入：若填的是纯文本模型（`deepseek-chat` / `deepseek-reasoner` / `gpt-3.5` 等），点识别会直接提示并**不发送请求**。
- 离线 OCR 仍是默认主路径（不联网、不花钱），大模型识别只是可选增强；页面顶部「🔧 环境自检（识别引擎状态）」可展开查看引擎状态。

RUN pip install --no-cache-dir -r requirements.txt

COPY . .

CMD streamlit run app.py --server.address=0.0.0.0 --server.port=8501

## 数据格式说明

上传文件为 UTF-8 编码的 CSV，第一行为表头。仓库内自带 `run_data.csv` 可直接用于演示：

| 日期 | 里程(km) | 时长(分钟) | 配速(min/km) | 平均心率 |
| --- | --- | --- | --- | --- |
| 2026-10-01 | 3.0 | 21 | 7.0 | 132 |
| 2026-10-06 | 4.2 | 27 | 6.4 | 142 |
| 2026-10-10 | 5.0 | 31 | 6.2 | 145 |

- **必需列**：`日期`、`里程(km)`、`时长(分钟)`、`配速(min/km)`、`平均心率`。缺任意一列时，页面会明确列出**缺失的列名**，不会静默失败。
- **日期列**：按日期解析，解析失败的行会给出说明并跳过。
- **数值列**：出现 NaN 的行会被剔除，页面提示被剔除的行数，避免「数据少了但没人知道」。
- 配速单位为 min/km（数值越小越快）；警校模式下自动折算为 1000 米用时。

## 数据合规与脱敏声明

- 仓库内 `run_data.csv` 及演示模式的预置结果，**全部为模拟数据**，由作者自行编造，不对应任何真实个人的训练记录。
- 作品运行过程中不采集、不存储、不上传用户文件到自有服务器；文件只在当前 Streamlit 会话内存中处理。
- 用户提交给自己的第三方 AI 服务的内容仅为聚合后的统计摘要与上传数据的文本摘要，不包含姓名、学号、身份证号、手机号等个人身份信息。
- 因此本作品**不含真实敏感数据**，符合赛事「严禁使用真实敏感数据」的要求。

## 已知限制与后续迭代

**已知限制**

1. 只接受 CSV，暂不支持 Excel / TCX / FIT 等运动设备原始格式。
2. 只做单次上传的分析，没有账号体系，也不做历史数据的长期存储与跨会话对比。
3. AI 结论的质量取决于所选模型；模型输出为自然语言建议，属参考性质，不构成医疗或训练处方。
4. 演示模式使用的是预置样例结果，与用户上传的真实数据无关（页面已有明显徽标提示）。
5. 警校模式的参考目标线是使用者自设的参考值，不涉及任何官方考核标准。
6. 截图识别（视觉大模型）的成功路径取决于是否配置了可用的 API Key；未配置时只能用离线 OCR。
7. 截图识别目前只在「第一赛道 + COROS PACE 4」版式上验证过，其它 App 版式需人工核对。

**后续迭代**

1. 支持 Excel / TCX / FIT 导入，接入常见运动 App 的导出格式。
2. 加入账号与历史记录，画出「周 / 月」维度的长期趋势与训练负荷。
3. 把单次 AI 调用改为结构化输出（JSON Schema），让训练方案可直接导出为周计划表。
4. 增加移动端适配，方便在操场上直接用手机看。
