# RUN ANALYZER｜跑步数据分析与体能训练方案生成器

把一份跑步记录（**截图**或 CSV）变成一份看得懂的分析结论和一份练得下去的训练方案。
内置「通用跑者」与「警校体能考核」双模式，默认的演示模式**不联网、不需要任何 API Key**。

- 在线访问：<https://runanalyzer-kjvqnr67d357hqecc4ordt.streamlit.app>（公开，无需注册）
- 源码：<https://github.com/www0255/run.analyzer>

## 1. 目标用户与场景

| 用户 | 场景 | 关心什么 |
| --- | --- | --- |
| 业余跑者 / 学生 / 健身入门 | 每周 2–4 次跑步，用手机 App 记录 | 我最近练得怎么样、下周怎么练 |
| 警校体能考核学员 | 1000 米测试备考 | 我现在折算 1000 米几秒、离目标差多少 |

现实约束：**大多数人没有 CSV，只有 App 里的记录截图**；也不愿意为了用一次 AI 去注册、配 Key。

## 2. 解决的问题

1. 运动 App 只给图表和数字，不给结论——不知道下一步练什么。
2. 想用大模型分析，先被 Base URL、API Key、401、超时挡住。
3. 设备给的是 min/km，体测看的是 1000 米多少秒，口径不一致。
4. 记录只存在截图里，手工录入成表格成本很高。

## 3. 核心功能

**① 截图转 CSV（数据入口）**

- 上传一张或多张跑步 App 的「运动记录详情页」截图，一张图 = 一次跑步。
- 双引擎：**离线 OCR（RapidOCR，不联网、不花钱，默认路径）** 与 **视觉大模型（DeepSeek 等 OpenAI 兼容接口，可选增强）**。
- 解析采用「标签锚定」：先定位 `公里 / 用时 / 平均配速 / 平均心率` 等中文标签，再取与其列对齐的数值，避免被地图上的公里点、天气、步频等干扰数字带偏。
- 结果进入**可编辑表格人工校正**，再导出 UTF-8 BOM CSV，或直接「用这份数据开始分析」。
- 单张识别失败只留空行并提示，不影响其余图片。

**② 双模式趋势分析**

- 通用跑者模式：里程 / 配速 / 心率趋势。
- 警校体能模式：配速自动折算 1000 米用时 + 折算趋势图 + 可拖动的「参考目标线」（默认 270 秒 = 4 分 30 秒）。
- 图表：三张独立趋势图（里程 / 配速 / 心率），曲线为平滑插值；汇总统计为**四项指标四方图**。

**③ 教练知识库驱动的 AI 方案**

专家身份、训练学规则、输出结构与医学边界都写在 `coach_knowledge.py`，作为 system 提示词注入；模型因此按固定结构产出：现状评估 / 风险提示 / 下周课表（表格）/ 递进原则 / 一句话提醒。

**④ 演示模式与降级**

默认开启，读取 `data/` 下的预置结果，零 Key 零网络；真实 AI 模式超时 30 秒，任何异常自动降级为预置结果并给出友好提示。

## 4. 技术与 AI 使用

- 技术栈：Python 3 · Streamlit · pandas · Plotly · OpenAI 兼容 SDK（`openai`）
- OCR：`rapidocr-onnxruntime`（版本按 Python 版本分别钉死，见 `requirements.txt`）
- 部署：Streamlit Community Cloud / 本地 / Docker
- 数据警务视角：作品本质是一条数据链路——**采集 → 清洗校验 → 指标折算 → 结论与决策建议**

## 5. AI 服务配置（Secrets 与预设）

配置优先级：**侧边栏手动填写 > Cloud Secrets**。四个键名：

| 键 | 作用 | 缺省 |
| --- | --- | --- |
| `AI_BASE_URL` | 接口地址 | `https://api.openai.com/v1` |
| `AI_MODEL` | 文本分析模型 | `gpt-4o-mini` |
| `VISION_MODEL` | 截图识别模型（必须支持图片输入） | 回退到 `AI_MODEL` |
| `AI_API_KEY` | 密钥（依次回退 `DEEPSEEK_API_KEY` → `OPENAI_API_KEY`） | 无 |

侧边栏有「服务商预设」：选 **DeepSeek** 自动填 `https://api.deepseek.com` + `deepseek-flash`（官方当前模型，支持图片输入）；切换预设不会清空已填的 Key。
若视觉模型填成纯文本模型（`deepseek-chat` / `deepseek-reasoner` / `gpt-3.5`），点识别会直接提示并**不发送请求**。

## 6. 部署与访问

### 方式一：Streamlit Community Cloud（在线版）

1. 用 GitHub 账号登录 <https://share.streamlit.io>。
2. New app → 选仓库 `www0255/run.analyzer` → 分支 `main` → 主文件 `app.py`。
3. 需要真实 AI 时，在 **Advanced settings → Secrets** 粘贴（**Key 只填后台，绝不提交进仓库**）：

```toml
AI_BASE_URL = "https://api.deepseek.com"
AI_API_KEY = "sk-你的key"
AI_MODEL = "deepseek-flash"
VISION_MODEL = "deepseek-flash"
```

4. Deploy 后得到公开链接；只演示演示模式则无需任何配置。

> Linux 上 OpenCV / onnxruntime 需要系统库，仓库根的 `packages.txt`（`libgl1` / `libglib2.0-0` / `libgomp1`）负责装好它们。

### 方式二：本地运行

```bash
pip install -r requirements.txt
streamlit run app.py
```

浏览器打开 <http://localhost:8501>。真实 AI 的 Key 可在侧边栏临时填写，或写入 `.streamlit/secrets.toml`（已在 `.gitignore` 中）。

### 方式三：Docker

```bash
docker build -t run-analyzer .
docker run -p 8501:8501 run-analyzer
```

页面顶部有「环境自检」可展开，逐项显示 OCR 引擎、cv2、onnxruntime、模型加载状态；识别异常时也会把这一层的真实原因显示出来。

## 7. 数据格式

上传 CSV 需 UTF-8 编码、第一行为表头。仓库自带 `run_data.csv` 可直接演示：

| 日期 | 里程(km) | 时长(分钟) | 配速(min/km) | 平均心率 |
| --- | --- | --- | --- | --- |
| 2026-10-01 | 3.0 | 21 | 7.0 | 132 |

- **必需列**：`日期`、`里程(km)`、`时长(分钟)`、`配速(min/km)`；缺列会逐条列出，不静默失败。
- **平均心率**：可选。缺失时心率曲线与心率统计自动跳过，其余功能正常。
- 日期解析失败的行会说明并跳过；数值 NaN 的行会被剔除并提示行数。

## 8. 数据合规与脱敏

- 仓库内所有跑步数据、截图与预置分析结果均为**模拟或自制数据**，不含任何真实个人记录。
- 上传的截图与 CSV 只在运行时内存中处理，不落盘、不上传到自建服务器。
- 送给第三方大模型的只有聚合后的统计摘要（或用户主动选择上传的截图），不含姓名、学号、手机号。
- API Key 只通过 Secrets 或侧边栏内存输入，**不写入仓库、不写入日志、不在页面显示**。
- 「参考目标线」是使用者自设的对照刻度，**不代表任何官方标准或体测达标认证**。

## 9. 使用到的开源项目

`streamlit`、`pandas`、`plotly`、`openai-python`、`rapidocr-onnxruntime`（含 onnxruntime / OpenCV 依赖）、Pillow。
页面视觉（CSS 主题层、3D 标题与控件）为本项目自制；除此之外**未使用第三方 UI 模板**。

## 10. 已知限制与后续迭代

1. 截图识别目前主要验证了「第一赛道 + COROS PACE 4」的记录详情页版式，其它 App 版式依赖兜底逻辑，需人工核对。
2. 视觉大模型的准确率取决于所选模型与图片质量；离线 OCR 无需 Key 但准确率中等，因此保留了人工校正环节。
3. 日期与时间粘连时可能出现歧义（如 `2026-11-107:00`），程序会按规则取一种读法并在页面提示核对。
4. 未提供账号体系与多用户隔离，适合个人或小范围使用。
5. 后续方向：TCX / FIT 直接导入、长期训练负荷（ATL/CTL）与伤病风险趋势、移动端适配。
