## 逐字稿

### 0:00-0:20（20 秒）开场
各位评委老师上午好，我是**数据警务技术专业**的学生。我的作品叫 **跑步数据分析与体能训练方案生成器，Run Analyzer**——**把一份跑步记录表，变成一份看得懂的结论和一份练得下去的方案。**

### 0:20-1:10（50 秒）痛点
我做这个作品，是因为三个卡点：
第一，跑步 App 给我的是一堆图表，但没人告诉我「下一步该练什么」；
第二，想用 AI 帮我分析，先得会配 Base URL、会填 Key、还要处理 401 和超时，大多数人卡在这一步就放弃了；
第三，我在警校，评测看的是 **1000 米多少秒**，而设备给我的单位是 **min/km**，口径不一致，得自己换算。
这三件事，我做进了一个网页里。

### 1:10-2:50（100 秒）作品介绍（一页 PPT 上半）
**一句话：上传一份 CSV，出结论、出方案。**
侧边栏有两个模式，radio 一点就切：
**通用跑者模式**——面向业余跑者、学生、健身入门的人，看里程、时长、配速、心率的变化趋势，再给训练建议；
**警校体能考核模式**——把配速直接折算成 **1000 米用时**，比如配速 6.2 就是 **6 分 12 秒**，画折算趋势图，再加一条我自己能拖动的**参考目标线**，默认 270 秒也就是 4 分 30 秒。**这里我要特别说明：这条线是使用者自己设置的参考值，不是任何官方标准，也不是体测达标认证。**
还有一件我最看重的事：**演示模式默认开着**，它不调用任何外部 API，直接从预置结果渲染，页面顶部有醒目的「演示模式 · 预置样例结果」徽标。**评委点一下就能出结果，不需要 Key，也不依赖现场网络。**

### 2:50-3:50（60 秒）技术架构与 AI 使用
这个作品本质是一条数据链路：**采集、清洗、指标、决策**——和我专业训练里做的事是同一件事。
技术上很朴素：Python + Streamlit 做界面，pandas 做校验清洗，Plotly 画交互图，openai SDK 走 OpenAI 兼容的 chat.completions，超时 30 秒。
界面不只会摆控件：背景是一层 three.js 的空间粒子场加 shader 渐变，压在内容下面（z-index -1），**不遮挡正文、也不截获点击**；帧率上限 30，切到后台自动暂停，机器不支持 WebGL 就整层退回纯 CSS 氛围——它是一个可以一键关掉的装饰层，不是一个炫技的阻塞项。
**AI 我用了两次，A 类和 B 类我都申报。**
**A 类，AI 在产品里：**上传数据后，把清洗后的统计摘要交给大模型，由它生成分析结论和训练方案——没有 AI，你只能看到图，拿不到结论。
**B 类，AI 在开发里：**需求梳理、页面骨架初稿、报错定位、文档与测试用例，我都在用 AI 起草；但每一段进仓库的代码我都读过、改过、能解释。
健壮性上：**任何异常——网络失败、401、超时——都会被捕获，页面显示友好提示并自动降级成演示结果，绝不把报错栈甩到页面上。**

### 3:50-5:00（70 秒）数据合规与验收对照
数据合规先说清楚：**仓库里的数据全部是我自己编的模拟数据，没有任何真实个人记录。**文件只在当前会话内存里处理，不落盘、不上传到我自己的服务器；送给第三方 AI 的也只有聚合后的统计摘要，不含姓名、学号、手机号。
对照最低验收 7 项：场景明确——两个真实人群；功能可用——上传、校验、分析、方案一条链路完整可用；云端可访问——已部署，链接在 README 和提交表里；数据合规——模拟数据；技术说明清楚——就在这一页；一页 PPT——**我自己做的，不是 AI 直接生成提交**；可复盘——README 里有部署步骤、数据格式、已知限制。
