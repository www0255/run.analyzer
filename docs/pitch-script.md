## 逐字稿

### 0:00-0:20（20 秒）开场
各位评委老师上午好，我是**数据警务技术专业**的学生。我的作品叫 **跑步数据分析与体能训练方案生成器，Run Analyzer**——**把一份跑步记录，变成一份看得懂的结论和一份练得下去的方案。**

### 0:20-1:10（50 秒）痛点
我做这个作品，是因为三个卡点：
第一，跑步 App 给我的是一堆曲线图，但没人告诉我「这个月我到底练得怎么样，下一步该练什么」；
第二，想用 AI 帮我分析，先得会配 Base URL、会填 Key、还要处理 401 和超时，大多数人卡在这一步就放弃了；
第三，我手里只有 App 的截图，没有表格，录不进去，分析就无从谈起。
这三件事，我做进了一个网页里。

### 1:10-2:50（100 秒）作品介绍（一页 PPT 上半）
**一句话：上传一份 CSV 或一张截图，出趋势、出汇总、出能力档案、出方案。**
链路只有一条，顺序是固定的：
**第一层，采集**——没有表格也没关系，App 的「运动记录详情页」截图可以直接识别成 CSV，离线 OCR 打底、不联网也能跑，识别完进可编辑表格，**人工核对过才进分析**；有 CSV 就直接上传。
**第二层，看过程**——里程、配速、心率三张趋势图，各一张、各自可读，不做成一张挤在一起的拼图。
**第三层，看总量**——汇总统计表给单次与平均，跑量统计给训练周数、周均、最大单周、最近一个月；月度柱状图和每周折线回答的是「练得够不够、稳不稳」。
**第四层，看能力**——六维雷达：心血管基础、最大摄氧量、耐力、速度、恢复质量、训练纪律，每个维度都附一条可核对的依据，比如「每跳推进 1.08 米，心率低于 150 的场次占 100%」。**样本少于 30 次时评分会向中位收缩**，因为 8 次记录算不出真实水平，我不想给假精度。
**第五层，出结论**——五段训练方案，加一个「本月统计」的月度复盘，按你选的月份单独算一次。
还有一件我最看重的事：**没配 Key 的环境里演示模式默认开着**，不调用任何外部 API，直接从预置结果渲染，页面顶部有醒目的「真实 AI 模式 / 演示模式」提示。**评委点一下就能出结果，不需要 Key，也不依赖现场网络。**

### 2:50-3:50（60 秒）技术架构与 AI 使用
这个作品本质是一条数据链路：**采集、清洗、指标、决策**——和我专业训练里做的事是同一件事。
技术上很朴素：Python + Streamlit 做界面，pandas 做校验清洗，Plotly 画交互图，openai SDK 走 OpenAI 兼容的 chat.completions，**超时 90 秒**，任何异常都自动降级成预置结果。
界面不只会摆控件：背景是一层 three.js 的空间粒子场加 shader 渐变，压在内容下面（z-index -1），**不遮挡正文、也不截获点击**；帧率上限 30，切到后台自动暂停，机器不支持 WebGL 就整层退回纯 CSS 氛围——它是一个可以一键关掉的装饰层，不是一个炫技的阻塞项。
**AI 我用了两次，A 类和 B 类我都申报。**
**A 类，AI 在产品里：**上传数据后，把清洗后的统计摘要交给大模型，由它生成分析结论和训练方案——没有 AI，你只能看到图，拿不到结论。
**B 类，AI 在开发里：**需求梳理、页面骨架初稿、报错定位、文档与测试用例，我都在用 AI 起草；但每一段进仓库的代码我都读过、改过、能解释。
健壮性上：**任何异常——网络失败、401、超时——都会被捕获，页面显示友好提示并自动降级成演示结果，绝不把报错栈甩到页面上。**

### 3:50-5:00（70 秒）数据合规与验收对照
数据合规先说清楚：**仓库里的数据全部是我自己编的模拟数据，没有任何真实个人记录。**文件只在当前会话内存里处理，不落盘、不上传到我自己的服务器；送给第三方 AI 的也只有聚合后的统计摘要，不含姓名、学号、手机号。
对照最低验收 7 项：场景明确——已经跑了几个月、想按月复盘的进阶跑者；功能可用——上传、校验、趋势、汇总、能力档案、方案一条链路完整可用；云端可访问——已部署，链接在 README 和提交表里；数据合规——模拟数据；技术说明清楚——就在这一页；一页 PPT——**我自己做的，不是 AI 直接生成提交**；可复盘——README 里有部署步骤、数据格式、已知限制。
